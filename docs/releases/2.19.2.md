# SD003 Framework 2.19.2

更新日: 2026-09-06。deployツールの版番号は3.5.0。SD003本体のみを更新し、他プロジェクトへの配布は行わない。

## 変更内容

- Codex実行正本で、可逆的な作業の完遂、承認直前までの準備、成果物単位の並列委譲と統合責任を定義した。必要な独立検証を残し、承認の繰り返しと価値の低いテストを避ける。
- 共通RULESとCodex手順の優先順位を明確にした。原資料・既存変更の保護、公開承認は維持する。
- Lead lockを実worktreeに対応させ、取得競合・別PIDからの解放・書込み失敗の誤成功を防ぐ。
- `.codex/check-framework-version.py`を追加し、Codexのセッション開始手順とsessionreadに一度だけ行う版比較を組み込んだ。
- 依頼ひな形と、公式情報の監視を登録するための指示をdocsへ保存した。公式サイトの定期監視は登録していない。

## 起動時の版比較

対象プロジェクトで`python .codex/check-framework-version.py`を実行する。ローカル更新元を自動解決できない場合は`--source <SD003本体の絶対パス>`か`SD003_SOURCE`を使う。

導入側と更新元のdeploy.ps1 / deploy.shのFRAMEWORK_VERSIONをそれぞれ照合する。更新があれば通知するが、起動時にファイルを上書きしたりネットワークへ接続したりしない。参照不能や版の不整合は未確認とし、依頼作業は続行する。

起動時の実行はNative/sessionreadの手順によるもので、OSの常駐監視や新しいCLI hookではない。この版をまだ取り込んでいない既存プロジェクトへ、本体の修正だけで新しい起動手順が自動注入されるわけではない。

版の一致はファイル内容の一致を保証しない。`.sd003-keep`等で保護したファイルは保持されるため、更新適用状況は実際の差分と検証結果で判断する。
