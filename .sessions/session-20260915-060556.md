6. **hook 2本が Windows で死んでいた件の真因特定と修正（commit `77736af`）**

   - **真因**: `hook-lint.sh` は `file_path` を POSIX 絶対パス前提で処理（`case "$fp" in /*)` のみ）。
     Windows の Claude Code が渡すのは `D:\claudecode\kb001\entities\concept\tools.md`
     （一時デバッグで生ペイロードを採取して確定）。ドライブレターが相対扱いになり
     `$ROOT/D:\...` → `cd` 失敗 → **exit 0 で無症状スキップ**
   - **実害**: 書き込み時の lint 検査と Stop 時の自動 save が発火しない。
     capture スキルが明示的に `lint` / `save` を打つ規律で覆われていたため表面化していなかった
   - **修正**: `fp=${fp//\\//}` で区切り正規化 + `[A-Za-z]:/*` を絶対パス扱いに追加。
     修正後、同一セッション内で台帳が生成され内容が POSIX 正規化されることを実測確認
   - `hook-stop.sh` / `hook-boot.sh` は `file_path` を受け取らないため同じ欠陥なし
     （SessionStart だけ生きていたことが「動いている」という誤った安心材料になっていた）

7. **レシピ R6 が Windows で静かに0件を返す件の特定と回避**

   - rg の出力はパス区切りが混在（引数部分 `/`・再帰部分 `\`）し、xargs が `\` を食う
   - さらに **この環境に rg の実体バイナリが無い**。`rg` は Claude Code が注入するシェル関数

   - 回避: `--path-separator //`（`/` 単体は MSYS2 が Git のインストール先に展開して弾かれる）+

   - `scripts/wiki` と hooks は rg を呼ばない（node 内蔵）ため影響は司書の手打ち検索のみ
