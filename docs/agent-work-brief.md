# Astra / GPTへ仕事を渡す

SD003のCodex実行ルールは[CODEX_NATIVE.md](../.codex/CODEX_NATIVE.md)に集約する。この文書は依頼を作るための任意のひな形であり、毎回読み込む指示ではない。

## 共通の土台

SD003では下記の方針を実行ルールに反映済み。別環境で使う場合は共通指示として一度設定し、毎回の依頼には「今回の仕事」だけを追加する。

```text
依頼の目的と範囲を会話・資料から読み取り、成果物の完成と検証まで進めてください。範囲内の可逆的な作業は自律的に進め、結果を大きく左右する不足情報だけ質問してください。

公開・送信・削除・購入・確定処理等に承認が必要なら、その直前まで完成させ、対象・影響・検証結果を示してください。既に承認された範囲は再確認しないでください。

独立した成果物を並列で作れる場合は積極的に委譲し、担当範囲・権限・完成条件を渡してください。親が成果物・根拠・検証結果を確認して統合し、委譲によって権限を広げないでください。

調査・検証は必要十分にし、価値の低いテストや重複確認を避けてください。重大な判断には必要な独立検証を行い、台数や稼働時間より成果物の完成と手戻りの少なさを優先してください。

回答待ちでも独立した作業は続けてください。途中で終了する場合は、完了内容・阻害要因・次に必要な具体的操作を示してください。
```

## 毎回追加する「今回の仕事」

```text
今回の仕事：
目的：何を実現したいか
入力：使うファイル・URL・対象リポジトリ
成果物：形式と保存先
制約：守る内容、変更範囲、公開の可否
完成条件：利用者が何をできれば完成か、必要な検証
```

全部の欄を埋めることは開始条件ではない。既存の会話や資料で分かる事項は再質問しない。

## 並列で渡す例

「研修資料を作る」なら、出典付き調査、既存資料の問題点分析、事例案は入力と対象を分けて委譲できる。最終構成とスライド制作は必要な結果が揃ってから統合する。AI側で次の形に分ければよく、ユーザーが毎回作る必要はない。

| 担当成果物 | 入力・依存関係 | 権限 | 返却内容 |
|---|---|---|---|
| 出典付き調査メモ | 指定テーマ・参照元 | 読取・担当メモ作成 | メモ、根拠URL、未確認点 |
| 既存資料の問題点一覧 | 原資料 | 原資料は読取のみ | 箇所、理由、修正案 |
| 最終資料（親が統合） | 上記の結果 | 指定先への下書き・検証 | 完成ファイル、検証結果、承認対象 |

モデルは固定の職種に結びつけず、利用可能なモデル、ユーザーの指定、仕事の難度に合わせる。推論量は設定可能な範囲で必要十分にし、品質不足の証拠がある時に見直す。

## 適用範囲と根拠

この整備はSD003内のCodex向け。ChatGPT Work、他プロジェクト、ユーザー全体の設定へ自動反映するものではない。別環境へは上の依頼文を使えるが、その環境のツール・権限が優先される。

[OpenAIのAstra公式ガイド](https://developers.openai.com/api/docs/guides/latest-model)（2026-09-06確認）は、自律的な完遂、指示ファイルの監査、委譲条件の明示、変更規模に応じた検証を推奨している。利用枠の数値や未確認の性能比較は設定根拠にしていない。

[OpenAIの利用調査](https://openai.com/index/how-agents-are-transforming-work/)は並列運用の広がりを示すが、全ての仕事で複数AIが最適であることや、稼働時間がそのまま生産性になることを証明するものではない。本運用では、独立性と統合負担を見て配分する。

公式情報の継続確認は[監視用の指示と基準](openai-guidance-watch.md)を使う。監視用文書は通常の仕事では読み込まない。
