# 正式コードレビュー指針

案件IDと正式なレビュー対象が明示されたWorkflow Reviewで読む。案件IDなしのFast Reviewは`AGENTS.md`と`.codex/CODEX_NATIVE.md`に従い、会話内で重大度順に報告する。

## 前提

- ユーザー向け報告は日本語。
- `git status --short`、対象差分、依頼書またはspecを確認する。
- build、test、lintは実行可能な範囲で確認する。失敗や未実行も重要なレビュー情報として扱い、レビューを拒否しない。
- 既存の未コミット変更を戻さない。

## レビュー観点

1. 仕様整合性・破壊的変更
2. 正しさ・境界条件・エラーハンドリング
3. セキュリティ・認証認可・秘密情報・危険な操作
4. 運用・可読性・重複・必要最小限のテスト

仕様の正本は案件内の依頼文書と`.sd/specs/**/spec.md`を優先する。旧`requirements.md`前提に固定しない。

## 重大度

| 重大度 | 基準 |
|---|---|
| Critical | データ消失、重大なセキュリティ侵害、復旧困難 |
| High | 機能不全、明確なバグ、重大な仕様逸脱 |
| Medium | 境界条件・運用上の不備、将来の障害要因 |
| Low | 可読性、命名、軽微な重複 |

## 出力

指摘を重大度順に統合し、各項目に次を含める。

- 場所
- 根拠
- 影響
- 具体的な修正案
- 必要なら再現手順または追加検証

最後に重大度別件数、実行した検証、未確認事項、承認または変更要求を示す。段階ごとの逐次出力やカバレッジ目標は必須としない。

正式報告書は`.sd/ai-coordination/workflow/review/{案件ID}/`に保存する。案件IDのないレビューではファイルを作らない。
