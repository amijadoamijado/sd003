### 備考

1. **deploy.ps1 は UTF-8 BOM + CRLF が必須**（PS5.1 の CP932 誤読対策・日本語コメント8箇所あり）。本セッションで一度 LF に壊した。原因は自分の python 編集で、読み込みを universal-newline（`newline` 未指定）、書き出しを `newline=''` にしたため CRLF→LF に変換されたこと。**読み書き両方に `newline=''` を指定する**のが正しい。復旧後は `file` コマンドで BOM・CRLF を確認し、`git diff --stat` が挿入行のみ（削除0）であることで無傷を証明した。deploy.sh は逆に **BOM厳禁・LF** なので取り違えないこと

2. **PowerShell で native git を呼ぶときの2点**（Phase 1b 実装で踏んだ）
   - `$ErrorActionPreference='Stop'` 配下では PS7.4+ が `$PSNativeCommandUseErrorActionPreference` により native コマンドの失敗を終了エラー化する。`Invoke-GitSafe` 内で両プリファレンスを**関数スコープに**設定して回避（戻り値で自動復帰するので後始末不要）
   - `Invoke-GitSafe -C $path rev-parse ...` と書くと `-C` を**PowerShellが関数のパラメータ名として解釈**して失敗する。git引数は配列 `@('-C', $path, ...)` で渡すこと

3. **deploy.sh は MSYS2 の fork コストで非常に遅い**（Phase 4 の600ファイルコピーで数分）。Bashツールの120秒タイムアウトを超えるため、実 run 検証はバックグラウンド実行＋ログファイル必須。なお Bashツールの `run_in_background` + パイプは結果を取りこぼすことがあり（"completed with no output"）、**ログへリダイレクトしてから別途 grep する**か Monitor を使うのが確実

4. **aa001 は並行して別セッションが動いている**。触る前に必ず `git log` と `git status` で他セッターの進捗を確認すること。前半では最後まで気づかず、台帳登録の直前に3コミット進んでいたことを発見した

5. **sd003 は public repo**。コミット対象に関与先データが混ざらないか毎回確認すること（今回 `materials/releases/` の 380MB zip が該当し gitignore した）
