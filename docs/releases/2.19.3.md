# SD003 Framework 2.19.3

更新日: 2026-09-19。deployツールの版番号は3.5.0のまま。既存プロジェクトは`/sd-upgrade .`で取り込む。

## 変更内容

- `scripts/run-hook.js`: Git Bash の候補を `bash -c "exit 0"` で試し、実際に起動できるものだけを使う。存在するのに起動直後に落ちる Git Bash（`Top-level not found`）を避ける。aa001 `02dfd4f` の取り込み。
- `scripts/run-hook.js`: フックに100秒の打ち切りを付けた（`SD003_HOOK_DEADLINE_MS` で変更可）。超えたら bash 以下のプロセスツリーを `taskkill /T /F` で止め、通す（fail-open）。
- sessionread（`.claude/commands`、`.agents`/`.grok` の Skill、`.sd/commands/specs`、`session-management.md`）: `archive-sessions.sh` は Bash ツール（Git Bash）で実行すると明記した。

## 背景

2.19.2 以前は、フックが WSL 未導入の `C:\WINDOWS\system32\bash.exe` を拾って起動直後に失敗し、実質動いていなかった。`run-hook.js` で本物の Git Bash を使うようになると、`block-commit-on-test-fail.sh` が `git commit` のたびに `npm test` を実行するようになった。

Windows では Claude Code がフックの timeout で node を止めても、bash と `npm test` は残って stdout/stderr を握り続ける。そのため PreToolUse が設定の120秒を超えて数分間終わらなかった（aa001 で7分超を観測）。打ち切りはこの待ちを止めるためのもの。

PowerShell から `bash` を呼ぶと、Machine PATH が User PATH より先に来るため WSL スタブが選ばれ、文字化けした WSL 導入案内が出る。

## 検証手順

```bash
# 打ち切り: 60秒眠る子を持つフックが約3秒で終わり、子が残らないこと
echo '{}' | SD003_HOOK_DEADLINE_MS=3000 node scripts/run-hook.js <slow-hook.sh> | cat
# 通常のフックは約1秒
echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | node scripts/run-hook.js .claude/hooks/block-clasp-deploy.sh
python .codex/check-framework-version.py --source D:/claudecode/sd003
python scripts/sync-cli-commands.py --check
```
